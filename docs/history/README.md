# AI 协作开发档案

这里保存 XSA 的开发过程本身：真实会话材料、忠实整理的开发历程、架构决策、实际使用的提示词、架构图与证据索引。目的不是写成功故事，而是让后来者理解每个设计为什么这样定、哪些判断被纠正过、哪些能力仍未实现。归档规范见本目录 `CONVERSATION_ARCHIVE_POLICY.md`（迁移自实验期文件）。

## 目录

- `narratives/`：忠实整理的开发历程。整理稿不是逐字原文，会明确标注依据与范围。
- `decisions/`：架构决策与纠偏记录（ADR），以稳定编号相互引用。
- `prompts/`：实际使用过的提示词与任务契约，注明使用方与日期。
- `diagrams/`：Mermaid 架构图及其演进版本，均为可渲染源码。
- `evidence/`：关联 PR、Commit、测试与运行记录的证据索引。
- `transcripts/`：脱敏后的逐轮会话原文。建立条件：有可核对的会话导出或用户明确提供的文本。截至 2026-11-02 尚无符合该条件的完整导出，故未创建此目录，不以整理稿冒充原文；后续补入时按规范标注来源与脱敏类别。

## 首个案例（2026-11-02）

用户在 ChatGPT 提出创建 GitHub 仓库的目标；ChatGPT 当前连接缺少建仓接口，而 Muse（Personal Agent）具备 GitHub 操作能力。于是 ChatGPT 形成任务契约，Muse 执行建仓与文件迁移，GitHub 保存成果与证据，再由 ChatGPT 读取证据、审核并继续推进。

它体现 XSA 的核心价值：一个 Agent 缺乏的能力，可以通过授权协作调用另一个专业 Agent 的能力，不需要让每个 Agent 都拥有所有工具。

注意：当前这一步依然依赖人工转发提示词。后续要通过 Event Bridge 验证自动接力，不能将其描述为已经实现。
